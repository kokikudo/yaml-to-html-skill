# HTML 生成のルール

このスキルの生成物は**オフラインで自己完結した安全なバンドル**。ここでの「生成」は
テンプレートへの流し込みであって、AI が HTML を書き起こすことではない。AI が書くのは
**narration JSON）**だけ。

## まず: AI は HTML を書かない

- マークアップの出所は `templates/index.html` と `templates/course.html` だけ。
- 見た目を変えたいときはテンプレートを直して再ビルドする。生成物を手で直さない。
- 「このコースだけ特別なレイアウトにする」はしない。教材が増えるほど差が保守不能になる。

## 禁止（生成物のどこにも入れない）

`scripts/validate_html.py` が機械的に検査し、見つかれば**失敗**する:

- 外部 `<script src=...>`
- 外部 CSS（`<link rel="stylesheet">` / リモート `@import`）
- リモートを読む `<iframe src=...>`（このバンドルは iframe 自体を使わない）
- `<object>` / `<embed>`
- `fetch(...)` / `XMLHttpRequest` / `WebSocket`
- `localStorage` / `sessionStorage` / `document.cookie`
- `window.parent` / `window.top` / `target="_top"` によるトップ遷移
- どこかへ送信するフォーム
- API キー・秘密情報
- `http://` / `https://` を含む文字列（オフライン自己完結には不要）

最後の 1 つがよく引っかかる。`see_also[].path` や `source.path` は**ラベル**であって
リンクではない。スキームを落として `developer.apple.com/documentation/...` の形で書く。
narration JSON やプロンプト本文に禁止トークン（`fetch(` など）を書いてしまうのも同じく失敗するので、
言い回しを変える。

## 許可

- インライン `<style>` / `<script>`
- ページ内で完結する操作（Step の切り替え、前へ / 次へ、出典へのジャンプ、コピーボタン）
- クリップボードへのコピー（`navigator.clipboard` + `textarea` フォールバック）

## ページ遷移とテーマ

- コースは**リンクで開く別ページ**。iframe を使わないので、Chrome / Edge / Firefox の
  どれでも `file://` のまま動く。
- 既定はライトテーマ。トグルは `document.documentElement` の `data-theme="dark"` を切り替える。
- **ストレージが使えない**ので、テーマはページをまたぐときに**リンクのハッシュ**で運ぶ:
  一覧 → コースは `views/<course>.html#theme=dark`、コース → 一覧は `../index.html#theme=dark`。
  リロードするとライトに戻る（仕様）。
- コースページのハッシュは `#step=<step id>`、出典を開いているときは `#fact=<fact id>`
  （ダーク時は `&theme=dark` が付く）。読み込み時にハッシュを見て、その位置から開く。

## UI の原則

- **1 画面 1 手順。** 右ペインには選択中の項目だけを出す。ハンズオンは並べて眺めるものでは
  なく、上から順に手を動かすもの。
- **左ペインは現在地。** 番号・活性表示・「全 N 手順」で、どこまで来たかが分かるようにする。
- **コードは全文。** 差分ではなくその時点のファイル全文を出す（スキーマがそう決めている）。
  コピーボタンを添える。
- **出典は 1 タップ先に置く。** 各 Step からタイトルのリンクで出典一覧に飛べるようにし、
  本文の途中に逐語を挟まない。読み進める邪魔をせず、確かめたい人はすぐ確かめられる状態。
- **作り手のメタ情報を受講者に見せない。** `origin`・fact の id・YAML のファイル名は UI に
  出さない（→ `template-contract.md`）。
- **アクセシビリティ。** 見出しの階層、ラベル付きのボタン、可視のフォーカス、十分なコントラスト、
  キーボード操作。ナビは `<button>`、ページ遷移は `<a>`（役割を混ぜない）。
- **レスポンシブ。** 狭い画面では 1 カラムに畳む。コードブロックは横スクロールさせ、
  ページ全体を横に流さない。
- **`prefers-reduced-motion` を尊重する。**

## narration JSON 側）

詳細は `narration-contract.md`。要点だけ:

- **画面のタイトルとコード以外の文章は、すべて受講者向けに書き起こす。** `lesson.yaml` の
  `why` / `outcome` / `expect` をそのまま出さない。
- **日本語。話し言葉に近いですます調。** 声に出して読める文章にする。
- **固有名詞は `` ` `` で囲む**（`<code>` になる）。
- **先回りして不安を消す注意書きを置く。** 「この時点ではまだビルドが通りません」など。
- **ドキュメントに無い事実を書かない。** 説明を足すのであって、仕様を足すのではない。

## 内容のルール（YAML 側）

- **YAML にある事実だけを出す。** レンダラは補完しない。空の項目はセクションごと出さない。
- **「まだできないこと」を消さない。** 「まだ検索には出ない」のような記述は、学習者が途中の
  状態を不具合と誤解しないための情報。
- **`observe` の確認を機械検証のように見せない。** 「目で見て確認」と明示する。
- **途中までの教材はそう見せる。** `scope.truncated` のときは概要の先頭に説明のバナー、
  カードに「途中まで」のチップ。黙って短い教材として出さない。
