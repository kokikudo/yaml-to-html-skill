# 受講者向け原稿（copy JSON）

`lesson.yaml` は**記録**であって教材の本文ではない。`why` は「なぜこの手順を置いたか」の
メモ、`outcome` は到達点の一行、`expect` は確認内容の要約——どれも作り手のための言葉で、
そのまま画面に出すと事務的な箇条書きになる。

そこで**受講者が読む文章はすべて別に書き起こす**。それが copy JSON（`--copy`）。

```
lesson.yaml   … タイトル / ファイルパス / ソースコード / 手順の順序 / 出典の対応
copy JSON     … 受講者が読む文章のすべて（導入・コードの説明・注意書き・確認の言い回し・出典の要旨）
```

**画面に出る文章のうち、タイトルとソースコード以外はここから来る。** copy が無い項目は
`lesson.yaml` の文へフォールバックするが、そのとき必ずビルド警告が出る。警告が出ている
教材は「まだ書かれていない」と考える。

## ビルドでの扱い

- `--copy path.json` で渡す。バンドルの `copy.json` に**マージして保存**され、次回以降
  `--copy` を省略しても保持される（コースを 1 つ足すだけの再ビルドで文章が消えない）。
- 部分的に渡してよい。渡した部分だけが上書きされる（辞書は再帰的にマージ）。

## 形

```jsonc
{
  "overview": {                     // コース一覧ページ
    "title": "App Intents ハンズオン",
    "lead": "概要本文。空行で段落を分ける",
    "notes": ["ページ下部に出る補足（任意）"],
    "source_note": "出典についての一言（任意）"
  },
  "courses": {
    "<コース id>": {                 // courses.json の id（既定は project.name のスラグ）
      "summary": "コースカードに出る 1〜2 文",
      "lead": "コース概要ページの導入。ここが最初に読まれる文章",
      "goal": "終えたときの状態（任意・省略時は goal.outcome）",
      "requirements_lead": "前提の前置き（任意）",
      "requirements": ["前提を書き直す（任意・lesson.yaml の順に対応）"],
      "scaffold_lead": "下ごしらえの前置き（任意）",
      "scaffold": ["下ごしらえの手順を書き直す（任意）"],
      "covers": ["扱うことを読者の言葉で（任意）"],
      "excludes": ["扱わないことを読者の言葉で（任意）"],
      "notes": ["概要ページの補足（任意）"],
      "truncated_note": "途中までのコースの説明（scope.truncated のとき）",

      "steps": {
        "<step id>": {
          "lead": "この手順の導入。なぜ今これをやるのか、前の手順とどう繋がるのか",
          "files": {
            "<lesson.yaml と同じ path>": "このコードが何をしているかの説明"
          },
          "notes": ["先回りして不安を消す注意書き"],
          "checkpoint": "ここまでで何が確認できるかの言い回し"
        }
      },

      "evidence": {
        "lead": "出典一覧ページの前置き（任意）",
        "facts": {
          "<fact id>": "その出典の日本語要旨。原文の隣に並ぶ"
        }
      }
    }
  }
}
```

`files` のキーは `lesson.yaml` の `path` と完全一致させる（ファイル名だけでも引き当てる）。
`steps` / `facts` のキーは `lesson.yaml` / `evidence.yaml` の id と一致させる。

## 書き方

- **話し言葉に近い、ですます調。** 声に出して読める文章にする。体言止めの箇条書きを
  並べない。
- **`lesson.yaml` の文を写さない。** `why` を語り直す。`expect` を言い換える。同じ内容でも、
  記録の言葉と教材の言葉は違う。
- **導入は「なぜ今これをやるのか」から始める。** 手順の titleだけでは、受講者は自分が
  何のために手を動かしているのか分からない。前の手順との繋がりを必ず書く。
- **固有名詞は `` ` `` で囲む。** 型名・API 名・ファイル名・製品名。日本語の中に埋もれる
  英単語が拾えるようになる（`<code>` として描画される）。
- **先回りして不安を消す。** 「この時点ではまだビルドが通りません」「反映まで数秒かかります」
  のような一文が、詰まったときに戻ってこられるかどうかを分ける。`notes` に書く。
- **出典の要旨は道案内として書く。** 原文の逐語訳ではなく、「この出典は何を言っているか」を
  1〜3 文で。原文はすぐ隣に併記されるので、正確さは原文が担保する。
- **段落は空行（`\n\n`）で分ける。** 1 段落が 4 行を超えたら切る。

## 書かないこと

- **`origin` / `origin_note` / `needs_facts` / fact の id / YAML のファイル名。**
  作り手のための情報で、受講者には意味がない（UI にも出ない）。
- **ドキュメントに無い事実。** 文章を足すのは説明であって、仕様の追加ではない。API の挙動を
  勝手に書かない。迷ったら `lesson.yaml` と `evidence.yaml` に無い断定を避ける。
- **HTML タグ。** 使えるのは段落の空行と `` ` `` だけ。
- **`http(s)://` から始まる URL。** 検証で落ちる。パスはスキームを落として書く。

## 最小例

```json
{
  "overview": {"lead": "…"},
  "courses": {
    "spotlightphotos": {
      "summary": "…",
      "lead": "…",
      "steps": {"st-entity": {"lead": "…", "checkpoint": "…"}},
      "evidence": {"facts": {"f-appentity-requirements": "…"}}
    }
  }
}
```

まとまった実例は `sample-copy.json`（4 手順・出典 6 件のコース 1 本）。
